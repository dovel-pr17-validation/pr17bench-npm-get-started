# The Personal Knowledge Library - Library Catalog

This document proposed the **libraries** that could make up the app's
knowledge collection, with example shelves and notebooks, when the app was
called My Notes.

**Status (1.2.0):** all eight libraries proposed here now ship as built-in
handbooks: Health & Wellbeing, Agriculture, Financial Literacy, Education &
Learning, Community Development, Skills & Careers, Home & Family, and South
Africa, with 16 shelves, 16 notebooks, and 49 illustrated pages. Their actual
shelves and pages are in [content/](../content/), and how they are written in
[content/README.md](../content/README.md). They began smaller than the shelves
proposed below, which remain ideas for growing them.

## The library question

The app had reached the organizational stage:

```text
Library → Shelf → Notebook → Note
```

The next product question is not simply which features to add. It is which
libraries should exist inside the broader knowledge library, and how to make
those libraries useful to both an individual and a community.

For a first public-facing catalog, favor a small number of high-value
libraries. Each should have a clear subject, practical shelves, and example
notebooks that make it easy to understand what belongs there. Additional
libraries can be introduced as the collection and community needs grow.

## Long-term catalog shape

As the resource grows, the broader **Knowledge Library** could contain all
eight subject libraries:

```text
Knowledge Library
├── Health & Wellbeing
├── Agriculture
├── Financial Literacy
├── Education & Learning
├── Community Development
├── Skills & Careers
├── Home & Family
└── South Africa Knowledge
```

This is an expansion direction, not a requirement to create every library at
once. Starting with five keeps the initial catalog understandable while
leaving room for a deeper, interconnected collection over time.

## Principles for the catalog

- **Start small:** launch with the five recommended libraries and expand when
  there is useful material and a clear audience for a new subject.
- **Make boundaries understandable:** choose names that help contributors
  decide where a resource belongs.
- **Keep the hierarchy useful:** shelves represent broad subtopics; notebooks
  collect related guides or notes; individual notes hold the actual knowledge.
- **Allow connections across subjects:** a resource may relate to more than
  one area. Use note links rather than duplicating the same content in several
  places.
- **Be locally relevant:** include South African context where it improves
  accuracy or usefulness, especially for public services, rights, and culture.
- **Treat sensitive topics carefully:** health, finance, legal, and public
  service material should be clearly sourced, dated where appropriate, and
  presented as educational information rather than a substitute for qualified
  professional advice.
- **Separate catalog design from seeded data:** this proposal describes a
  possible catalog. Any future decision to add starter libraries, shelves, or
  notebooks to the app should preserve users' existing organization and be
  handled as an intentional product and data-migration change.

## Direction

The long-term opportunity is for the app to grow from a personal note-taking
app into a **community knowledge library platform**: a place where useful
information can be organized, preserved, and connected across subjects. The
five-library Version 1 catalog is a practical first step toward that vision;
the additional three libraries provide a path to broader coverage when the
collection is ready.
